# Table de correspondance théorie ↔ code — `federated_optimizing_trigger_policy` / `federated_policy_to_flips`

Référence normative : `docs/theory/threat_model.tex` (Part 0 — Setup, Part A — Mean aggregation).
Le fichier ne contient pas de Part B/C malgré l'en-tête qui les annonce ; sans objet pour cet
audit (les deux modules audités implémentent `(P^mean)`, Part A).

Convention de lecture : `beta` (code) est le taux **LOCAL** — la fraction du shard d'un SEUL
worker corrompu qu'il peut flipper — conformément au choix explicite et documenté de
`federated_optimizing_trigger_policy` (voir §2.2 du rapport). C'est `theta_theory / gamma` dans
la notation de la référence (`beta` du dépôt ↔ `β/γ` du document ; le `β` global du document
n'a pas de variable dédiée dans le code). Cette table utilise donc `beta_local` pour désigner la
variable code `beta`, afin de ne jamais confondre les deux échelles.
